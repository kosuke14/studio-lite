# Plan: Add RBXLX/RBXMX XML Format Support

## Context
Studio Lite currently only supports binary Roblox files (RBXL, RBXM) via `rbxBinaryParser.js`. The XML format (RBXLX for places, RBXMX for models) is used by older Roblox Studio exports and some tooling. The goal is to add a pure-JS XML parser that converts these files into the same instance data structure the binary parser produces, then integrate it seamlessly.

## What the binary parser produces
The `decode(ab)` function returns an array of root instances. Each instance has:
- `ClassName`: string (e.g. "Part", "Workspace")
- `Children`: array of child instances
- Properties like `Name` (string), `CFrame` (object with `Position:{X,Y,Z}` and `Components` array of 12 floats), `Size` ({X,Y,Z}), `Color3` ({R,G,B} 0-1), `BrickColor` ({Name, Color:{R,G,B}}), `Shape` (string), `Material` (string), `Transparency` (number), `Source` (string), `MeshId`/`TextureId` (strings), etc.

## XML format structure (RBXLX/RBXMX)
```xml
<?xml version="1.0" encoding="utf-8"?>
<roblox version="4">
  <Meta name="ExplicitAutoJoints">true</Meta>
  <Item class="DataModel">
    <Item class="Workspace" referent="rbxid_1">
      <Properties>
        <string name="Name">Workspace</string>
        <bool name="FilteringEnabled">true</bool>
        <CoordinateFrame name="CameraCFrame">
          <X>0</X><Y>0</Y><Z>0</Z>
          <R00>1</R00><R01>0</R01><R02>0</R02>
          <R10>0</R10><R11>1</R11><R12>0</R12>
          <R20>0</R20><R21>0</R21><R22>1</R22>
        </CoordinateFrame>
      </Properties>
      <Item class="Part" referent="rbxid_2">
        <Properties>
          <string name="Name">MyPart</string>
          <Vector3 name="Size"><X>4</X><Y>1</Y><Z>2</Z></Vector3>
          <CoordinateFrame name="CFrame">...</CoordinateFrame>
          <Color3 name="Color3"><R>1</R><G>0</G><B>0</B></Color3>
          <Content name="Material"><url>rbxasset://...</url></Content>
        </Properties>
      </Item>
    </Item>
  </Item>
  <Item class="Lighting">...</Item>
  <SharedStrings>...</SharedStrings>
</roblox>
```

Key XML type tags and their content:
- `string`, `ProtectedString` → text content
- `bool` → "true" or "false"
- `int`, `int64` → integer text
- `float` → float text (also "INF", "-INF", "NAN")
- `double` → float text
- `Vector3` → `<X>`, `<Y>`, `<Z>` child tags with float text
- `Vector2` → `<X>`, `<Y>`
- `CoordinateFrame` (CFrame) → `<X>`, `<Y>`, `<Z>`, `<R00>`-`<R22>` child tags
- `Color3` → either `<R>`, `<G>`, `<B>` child tags, or a packed uint32 as text
- `Color3uint8` → packed uint32 as text
- `Content` → `<url>text</url>`, `<uri>text</uri>`, or `<null/>`
- `ContentId` → same as Content
- `Enum` → integer text
- `UDim` → `<S>`, `<O>`
- `UDim2` → `<XS>`, `<XO>`, `<YS>`, `<YO>`
- `BrickColor` → integer text (packed BrickColor number)
- `PhysicalProperties` → nested tags
- `Ray` → `<Origin>`, `<Direction>` (Vector3s)
- `Rect` → `<Min>`, `<Max>` (Vector2s)
- `NumberRange``, `NumberSequence`, `ColorSequence` → nested structures
- `Axes`, `Faces` → bitflag text

Parent-child relationships are encoded via nesting of `<Item>` elements.

## Implementation

### Step 1: Create `app/datamodel/rbxXmlParser.js`
A new XML parser that reads an ArrayBuffer (UTF-8 XML text), parses it using the browser's DOMParser, and converts it into the same instance array format as the binary parser.

Core approach:
1. Decode the ArrayBuffer to a string using TextDecoder (UTF-8)
2. Parse with `new DOMParser().parseFromString(xmlString, 'text/xml')`
3. Walk `<Item>` elements recursively
4. For each `<Item>`, create an instance object `{ClassName, Children: []}`
5. Within `<Properties>`, read each property element by its tag name and `name` attribute
6. Convert XML property values to the exact JS objects the binary parser produces

Value type converters (mapping XML tag → JS object):
- `string`/`ProtectedString` → string
- `bool` → boolean
- `int`/`int64` → number
- `float`/`double` → number (handle INF/-INF/NAN)
- `Vector3` → `{X, Y, Z}` floats
- `Vector2` → `{X, Y}` floats
- `CoordinateFrame` → `{Position: {X,Y,Z}, Components: [X,Y,Z, R00,R10,R20, R01,R11,R21, R02,R12,R22]}` — the binary parser stores the rotation matrix in column-major order (indices 3-11). The renderer uses `Components[3,6,9]` / `Components[4,7,10]` / `Components[5,8,11]` as rows of a row-major matrix passed to `Matrix4.fromArray`, confirming this layout.
- `Color3` → `{R, G, B}` floats (0-1). Handle both R/G/B tag format and packed uint32
- `Color3uint8` → `{R, G, B}` floats (0-1) — decoded from packed uint32
- `Content`/`ContentId` → string (from `<url>`/`<uri>` child, or empty)
- `Enum` → number
- `BrickColor` → `{Name: "...", Color: {R, G, B}}` — decode from BrickColor integer
- `UDim`/`UDim2` → keep as-is or convert to simple objects
- All other types → string representation or skip gracefully

### Step 2: Modify `app/rendering/StudioLiteRenderer.js`
In `loadPlace(ab)`:
1. Check if the file starts with XML signature bytes (`<?xml` or `<roblox`)
2. If XML: use `parseRbxXml(ab)` instead of `decode(ab)`
3. If binary: use existing `decode(ab)`

Detection logic: Read the first few bytes of the ArrayBuffer as text. If it matches XML patterns, use the XML parser; otherwise fall back to binary.

### Step 3: Update `app/app.js`
- Update the onboarding label from `(binary RBXL/RBXM only)` to `(RBXL/RBXM/RBXLX/RBXMX)`
- Update the remote load dialog instructions similarly
- Update the file input accept attribute if present

### Step 4: Create `app/datamodel/brickColorMap.js` (or inline)
A mapping from BrickColor integer IDs to RGB values, needed for decoding `<int name="BrickColor">194</int>` in XML files. This is a well-known Roblox constant table (~128 colors). Include only the most common ones to keep file size reasonable, with a fallback for unknown IDs.
